How the prediction works

1 · Graph of Shimla roads

Thirteen localities are nodes; 18 road segments are weighted edges carrying distance, road name and a congestion factor. Stored as an adjacency list: unordered_map<string, vector<Edge>>.

2 · Min-heap + Dijkstra

Routes are computed with Dijkstra using a template min-heap priority queue. Drive routing minimises travel time; walking routing minimises distance, so the same graph answers "how far do I walk from this lot?".

3 · Occupancy model

Each lot has capacity, price, popularity and a demand curve. Free slots at t+20 min = free now − (arrivals − departures) × 20, where arrivals scale with demand and traffic. Confidence falls when the lot is near empty or near full.

Data structures used (all in C++)

  • Min-heap — Dijkstra's frontier and top-K parking selection.
  • Graph (adjacency list) — roads and localities.
  • Hash maps — node table, zone table, booked-slot counters.
  • Vectors / arrays — per-lot 5-step availability timeline (+0…+60 min).
  • Stable sort — final ranking of candidate lots by score.
  • Stack (recursion via prev[]) — path reconstruction after Dijkstra.

Scoring

score = 32% predicted free slots
      + 26% drive time
      + 17% walking distance to destination
      + 12% price
      + 13% convenience (covered / CCTV / guard / EV)

If a lot is predicted to be full the score is cut by 40% and it is flagged as almost full instead of hidden — the driver still sees the risk.

Engine output (live)
